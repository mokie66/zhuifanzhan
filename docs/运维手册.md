# 运维手册

面向日常维护。核心是两件事：**采集源会失效，需要持续换**；**发布了新版本，需要让用户拿到**。

---

## 一、维护节奏

| 频率 | 做什么 | 命令 |
| --- | --- | --- |
| 每周 | 复检采集源可用性 | `npm run verify:taxonomy` 或 App 内「资源源 → 复检可用性」 |
| 每周 | 更新源列表（换失效源） | 见 [三、采集源换域名](#三采集源换域名) |
| 每月 | 完整回归验证 | `npm run verify:all` |
| 按需 | 发新版本 | 见 [五、发布流程](#五发布流程) |

**为什么必须定期做**：实测 60 个采集源里 **5 个已彻底失效**（域名被抢注、关站、改成需要鉴权）。
源站的寿命通常只有几个月到一两年。

---

## 二、检查源状态

### 方式 A：App 内（最方便）

进「我的 → 资源源」，点右上角「复检可用性」。会并发探测所有启用的源，显示：

```
● 量子资源  w100   可用 · 16.0 万资源 · 451ms
● 非凡资源  w95    可用 · 9.9 万资源 · 356ms
● 某某资源  w80    不可用 · HTTP 404
```

绿灯可继续用，红灯需要处理。

### 方式 B：命令行（批量、可留档）

```bash
npm run verify:taxonomy
```

输出每个源的分类表抓取情况。抓不到分类表 = 源挂了。

### 方式 C：直接测单个源

```bash
node -e "fetch('http://localhost:5173/collect/lzi?ac=list').then(r=>r.text()).then(t=>console.log(t.slice(0,150)))"
```

`lzi` 是源的 key。替换成你要测的源。能返回 JSON 且含 `"total"` 就是正常。

## 三、采集源换域名

源站换域名是**最频繁的维护动作**。有三种更新途径，选最合适的。

### 途径 1：远程配置更新（推荐，APK 用户无需重装）

**适用**：已经发布了 APK 给朋友，不想让他们重新装。

1. 在任意可访问的地方放一份 `sources.json`（GitHub Gist / 自己的站点 / 对象存储直链均可）
2. 用户或你本人在 App 内「资源源 → 从远程地址更新」填入该 URL
3. 更新后自动生效，无需重装

配置文件格式：

```json
{
  "version": 2,
  "updatedAt": "2026-10-20",
  "sources": [
    {
      "key": "lzi",
      "name": "量子资源",
      "api": "http://cj.lziapi.com/api.php/provide/vod/",
      "enabled": true,
      "weight": 100,
      "note": "备注（可选）"
    }
  ]
}
```

**校验规则**（远程配置被当作不可信输入处理）：

- `key` 只允许 `[a-zA-Z0-9_-]`，1~32 字符 —— 因为它会进 URL 路径和 nginx location，不允许斜杠和点号（防路径穿越）
- `api` 必须是 `http` / `https`
- `key` 重复的会被丢弃
- 至少要有 1 个合法源，否则整份配置被拒

### 途径 2：内置源列表（改代码，重新构建）

**适用**：自己维护、愿意重新构建。

编辑 `src/api/sources.js` 的 `BUNDLED_SOURCES`：

```js
{
  key: 'lzi',                          // URL 里用的标识，改动会导致老链接失效
  name: '量子资源',                     // 界面显示名
  api: 'http://cj.lziapi.com/api.php/provide/vod/',
  enabled: true,
  weight: 100,                         // 聚合优先级，越高越优先
  note: '延迟最低，实测可播',
}
```

改完后：

- **网页版**：必须 `npm run gen:nginx` 重新生成服务端代理配置并重载 nginx
  （因为 `/collect/<key>` 的 location 是按这个列表生成的）
- **App 版**：`npm run build && npx cap sync android` 后重新打包

### 途径 3：App 内手动粘贴（应急）

**适用**：临时试一个源，或远程地址不可用。

「资源源 → 手动粘贴配置」直接贴 JSON。优先级最高，会覆盖远程配置。

## 四、找不到可用源怎么办

### 方法 1：找同一资源站的备用域名

资源站常同时有多个域名。已知的例子：

```
天涯：  tyyszy.com      / tyyszyapi.com
量子：  cj.lziapi.com   / lzizy1.com
非凡：  cj.ffzyapi.com  / ffzy.tv  / ffzy1.tv
暴风：  bfzyapi.com     / app.bfzyapi.com
```

先把主域名的**主机名换掉**，路径 `/api.php/provide/vod/` 通常不变。

### 方法 2：从 TVBox / 影视仓配置里提取

这是**最有效的批量来源**。TVBox 配置 JSON 里 `type: 1` 的条目就是苹果CMS 采集接口：

```json
{"sites": [{"key":"量子","name":"量子","type":1,"api":"https://cj.lziapi.com/api.php/provide/vod/"}]}
```

操作：

1. 找一个 TVBox / 影视仓配置地址（社区里这类聚合很多）
2. 下载配置 JSON（可能是 base64 编码，也可能以 `.webp` 伪装，还可能有 `//` 注释行）
3. 提取所有 `type === 1` 的 `api` 字段
4. 填进 `sources.json`

**实测经验**：一次可以提取出几十个候选源，但**能用的通常只有三分之一**。所以要用下面的脚本筛。

### 方法 3：脚本批量筛（推荐）

```bash
# 1. 把候选地址写进文件，每行一个，# 开头为注释
cat > candidates.txt <<'EOF'
http://cj.lziapi.com/api.php/provide/vod/
https://bfzyapi.com/api.php/provide/vod/
http://tyyszy.com/api.php/provide/vod
EOF

# 2. 批量体检
node scripts/verify-taxonomy.mjs   # 或参考 verify-flow 的写法自行批量
```

筛选标准（按重要性）：

1. **能返回 JSON 且 code=1** —— 最基本
2. **含 m3u8 直链线路** —— 没有直链的源播不了（解析型线路前端无法播）
3. **有最近 24h 更新** —— 不更新的源等于死源
4. **延迟 < 3s** —— 太慢会拖垮首屏
5. **分类表完整** —— 缺分类会导致列表页取不到内容

**注意**：部分源会返回 HTML 错误页而非 JSON（关站页、跳转页、JWT 鉴权页）。
这类必须靠结构校验拦住，不能只看「能否解析」—— `config.js` 的 `validateConfig` 已做校验。

## 五、发布流程

### 网页版

```bash
npm run verify:all              # 1. 先验证，别把坏版本发出去
npm run build                   # 2. 构建
npm run gen:nginx               # 3. 源列表若改过，重新生成代理配置
# 4. 把 dist/ 上传到服务器，重载 nginx
```

服务器 nginx 需要 `include` 生成的 `deploy/nginx-collect.conf`，否则线上会重现 CORS 问题。

### APK

```bash
# 首次发布前先生成签名密钥（只需一次）
powershell -ExecutionPolicy Bypass -File scripts\gen-keystore.ps1

# 之后每次发布
powershell -ExecutionPolicy Bypass -File scripts\build-apk.ps1 -Release
```

产物：`android/app/build/outputs/apk/release/app-release.apk`

用户安装：

```bash
adb install -r app-release.apk
```

**重要**：release 版能覆盖安装 debug 版吗？**不能**（签名不同，必须卸载重装）。
所以第一次就该发布 release 版。

## 六、密钥管理（最容易出大事的地方）

```
密钥库：    android/zhuifan-release.jks
口令文件：  android/keystore.properties
```

**这两个文件丢失的后果**：无法发布能覆盖升级的新版本。用户必须卸载重装，本地收藏与观看记录全部丢失。

**必须做的事**：

1. **立即备份**到至少两个地方（密码管理器 + 离线存储）
2. **确认不要提交**：已被 `.gitignore` 覆盖（`*.jks` / `keystore.properties`），但提交前自己 `git status` 确认一遍
3. **不要填真实身份信息**到证书主题——证书会打进 APK，任何人 `keytool` 一读就能看到。
   默认用的是中性信息 `CN=Zhuifan, OU=Personal, O=Personal, L=Unknown, ST=Unknown, C=CN`

备份检查：

```powershell
# 确认密钥不在版本控制里
git status --short | Select-String "jks|keystore"

# 确认 APK 里没夹带密钥
Add-Type -AssemblyName System.IO.Compression.FileSystem
$z=[IO.Compression.ZipFile]::OpenRead((Resolve-Path 'android\app\build\outputs\apk\release\app-release.apk'))
$z.Entries | Where-Object { $_.FullName -match '\.jks$|keystore\.properties|\.pem$|\.key$' }
$z.Dispose()
```

## 七、故障排查

### 现象：页面空白 / 没有任何数据

```bash
# 1. 代理是否正常（最常出问题）
node -e "fetch('http://localhost:5173/collect/lzi?ac=list').then(r=>r.text()).then(t=>console.log(t.slice(0,150)))"
```

| 结果 | 原因 | 处理 |
| --- | --- | --- |
| 返回 JSON | 代理正常，问题在源或聚合层 | 跑 `npm run verify:flow` 看哪一步断 |
| 返回 404 | dev server 刚启动还在预构建依赖 | **等 2~5 秒重试**（启动瞬间中间件未挂载完成） |
| 返回 504 | 源站超时或限流 | 换源，或用设置页复检 |
| 连接被拒 | dev server 没起来 | `npm run dev` |

### 现象：某些片子显示「暂不可播」

**正常现象**。该片在当前源只有解析型线路（`/share/<hash>`），前端无法直接播。

处理：详情页点「换源」，找有直链线路的源。跨源换源会自动聚合，通常能找到。

### 现象：播放报错 / 黑屏

1. 点右上角「换线」，选标着**「直链」**的线路
2. 如果所有线路都不行，该片源可能已失效，换源
3. 检查是否 http 资源在 https 页面下被拦（`utils/media.js` 会自动套流代理，但代理需要服务器支持 `/collect/_stream`）

### 现象：dev server 频繁崩溃

历史原因：Windows 上编辑器原子写入产生的临时目录会让 Vite 的文件监视器抛 `EBUSY`。

已在 `vite.config.js` 里加忽略规则：

```js
server: {
  watch: { ignored: ['**/.*.tmpdir/**', '**/*.tmp', '**/*.swp', '**/.~*'] },
}
```

如果还崩，看报错里的路径并加进 `ignored`。

### 现象：构建 APK 报「无效的源发行版：21」

JDK 版本不够。Capacitor 8 要求 **JDK 21+**。

```powershell
winget install --id Microsoft.OpenJDK.21
```

`build-apk.ps1` 会自动按版本号降序挑选最高的 JDK，装了多个也不会选错。

### 现象：PowerShell 脚本报语法错误

本仓库的 `.ps1` 必须保存为 **UTF-8 with BOM**。

Windows PowerShell 5.1 读取无 BOM 的 UTF-8 脚本时会按系统 ANSI 编码（中文环境即 GBK）解码，
中文注释被破坏后会导致解析失败。如果你用编辑器改过这些脚本，请检查 BOM 还在不在。

### 现象：改了源列表但网页版不生效

浏览器版走服务端代理，代理的 location 是按**内置源列表**生成的。所以：

```bash
npm run gen:nginx      # 重新生成
# 然后重载 nginx
```

App 版直连源站，没有这个限制。

## 八、完整验证清单

改动后按需要跑：

```bash
npm run verify:all          # 全部（需 dev server 运行中）
```

单项说明：

| 脚本 | 验证什么 | 期望 |
| --- | --- | --- |
| `verify:config` | 源配置校验（含畸形/恶意输入） | 43/43 |
| `verify:storage` | 收藏去重、进度按线路隔离、快照瘦身 | 24/24 |
| `verify:taxonomy` | 分类翻译准确率 | 100% |
| `verify:flow` | 全流程 + **真实拉取 m3u8/ts 分片** | 19/19 |

`verify:flow` 是唯一会真实验证播放链路的——它会拉取 m3u8、变体清单和首个 ts 分片。
**只看结果数字不够，要确认「首个 ts 分片可拉取」那行出现且字节数 > 0**。

## 九、备份清单

需要备份的：

| 项 | 位置 | 重要性 |
| --- | --- | --- |
| **签名密钥** | `android/zhuifan-release.jks` + `keystore.properties` | 🔴 丢失不可恢复 |
| 源配置 | App 内「资源源 → 复制当前配置」导出 | 🟡 可重建但麻烦 |
| 源代码 | 你自己的版本控制 | 🟡 |

不需要备份（可重建）：`node_modules/`、`dist/`、`android/build/`、`android/app/build/`

## 十、性能与成本参考

| 项 | 实测值 |
| --- | --- |
| 单源列表请求 | 300ms ~ 6s（源站差异大） |
| 7 源并发聚合 | 约 2 ~ 8s 出首页 |
| 服务器带宽占用 | **极低** —— 视频流走用户直连 CDN，服务器只转发 JSON |
| APK 体积 | release 3.28 MB |
| 首页缓存 | 3 分钟 |
| 分类表缓存 | 30 分钟 |

带宽极低这点很重要：**服务器只需要很小的配置**（2核2G 足够），因为最大的流量（视频）不经过它。
