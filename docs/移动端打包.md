# 移动端打包（APK）

本文档说明如何把本项目打包成可安装到手机的 Android App，以及为什么这么做。

---

## 一、核心收益：打包后不需要服务器

这是最关键的一点，值得先说清楚。

浏览器版调采集接口有两个限制：

| 限制 | 原因 |
| --- | --- |
| CORS | 采集源不返回 `Access-Control-Allow-Origin`，浏览器直连被拦 |
| 混合内容 | 部分源是 http，页面在 https 下同样被拦 |

所以浏览器版**必须**有服务器做 `/collect` 代理（开发用 vite 中间件，生产用 nginx）。

App 版没有这两个限制——**请求由 Capacitor 原生层发出，不经过 WebView 的同源策略**，可以直接连采集源。

于是：

| | 浏览器版 | App 版 |
| --- | --- | --- |
| API 请求 | 必须经代理绕 CORS | 原生直连源站 |
| 需要服务器 | 需要 | **不需要** |
| ICP 备案 | 绕不开 | **不存在** |
| 视频流 | CDN 直连 | CDN 直连 |

**APK 装到手机上，只需要能上网就能用。** 这正好绕开了备案与部署的全部问题。

代码上这层差异收敛在 `src/api/transport.js`，上层业务代码完全无感：

```js
if (isNative()) {
  // App：Capacitor 原生 HTTP 直连源站
} else {
  // 浏览器：走同源代理 /collect/<key>
}
```

## 二、工具链要求

| 组件 | 最低版本 | 说明 |
| --- | --- | --- |
| **JDK** | **21** | Capacitor 8 的 Android 工程按 Java 21 编译。用 17 或更低会报 `无效的源发行版：21` |
| Android SDK | platform-tools + `platforms;android-36` + `build-tools;36.0.0` | 版本号由 `android/variables.gradle` 的 `compileSdkVersion` 决定 |
| Gradle | 8.14.3 | 由 wrapper 自动下载，无需手装 |
| Node.js | 18+ | 用于 `npm run build` 与 Capacitor CLI |

**最容易踩的坑是 JDK 版本。** Capacitor 8 要求 **JDK 21+**，而很多人机器上装的是
JDK 8 或 17（比如跟 Android Studio 或旧项目一起装的）。用错版本会在 Gradle 阶段直接失败。

构建脚本会**自动按版本号降序挑选最高的 JDK**，所以装了多个也不会选错。

### 从零搭建

```powershell
# 1. JDK 21
winget install --id Microsoft.OpenJDK.21

# 2. Android 命令行工具
#    下载 https://dl.google.com/android/repository/commandlinetools-win-*_latest.zip
#    解压，使其目录结构为：
#      <SDK>\cmdline-tools\latest\bin\sdkmanager.bat
#    在 <SDK>\licenses\android-sdk-license 写入许可哈希（或直接交互式接受）

# 3. 安装所需组件
sdkmanager.bat --sdk_root=<SDK> "platform-tools" "platforms;android-36" "build-tools;36.0.0"

# 4. 告诉构建脚本 SDK 在哪（二选一）
setx ANDROID_HOME "<SDK>"
# 或者只在本工程生效：在 android/local.properties 写 sdk.dir=<SDK>
```

## 三、构建

### 推荐方式：一键脚本

```powershell
# debug 包
powershell -ExecutionPolicy Bypass -File scripts\build-apk.ps1

# release 包（需先配置签名，见第五节）
powershell -ExecutionPolicy Bypass -File scripts\build-apk.ps1 -Release

# 只重跑 gradle（改过原生代码时用，快很多）
powershell -ExecutionPolicy Bypass -File scripts\build-apk.ps1 -SkipWeb
```

脚本会自动完成：定位 JDK 与 SDK → 补装缺失的 SDK 组件 → 构建 web → 同步 → Gradle 构建 → 报告产物与签名状态。

产物位置：

```
debug:   android/app/build/outputs/apk/debug/app-debug.apk
release: android/app/build/outputs/apk/release/app-release.apk
```

### 手动分步（便于排查问题）

```bash
npm run build          # 1. 构建 web 产物到 dist/
npx cap sync android   # 2. 把 dist/ 复制进 android 工程
npx cap open android   # 3. 需要图形化调试时打开 Android Studio
```

手动跑 gradle 时，环境变量必须指向 JDK 21 与 SDK（路径按你自己的环境填）：

```powershell
$env:JAVA_HOME    = '<你的 JDK 21 目录>'
$env:ANDROID_HOME = '<你的 Android SDK 目录>'
cd android
.\gradlew.bat assembleDebug
```

> 注意：本仓库的 `.ps1` 脚本均保存为 **UTF-8 with BOM**。
> 这不是随便加的——Windows PowerShell 5.1 读取无 BOM 的 UTF-8 脚本时会按系统 ANSI 编码
> （中文环境即 GBK）解码，中文注释会被破坏成乱码，导致脚本解析失败。
> 如果你用编辑器改动这些脚本，请保持 BOM。

## 四、关键配置说明

`capacitor.config.json`：

```json
{
  "appId": "com.zhuifan.app",
  "appName": "追番站",
  "webDir": "dist",
  "server": { "androidScheme": "https" },
  "android": {
    "allowMixedContent": true,      // ← 必须。部分 m3u8 是 http，不开则无法播放
    "webContentsDebuggingEnabled": true
  },
  "plugins": { "CapacitorHttp": { "enabled": true } }   // ← 必须。原生 HTTP 绕过 CORS
}
```

两个 `← 必须` 的配置如果漏掉，会分别导致：**视频播不了** 和 **接口连不上**。

## 五、远程配置下发（维护的关键）

### 为什么必须做

采集源换域名极其频繁——实测 60 个源里 **5 个已彻底失效**，多个源同时存在备用域名
（天涯有 `tyyszy.com` / `tyyszyapi.com`，量子有 `cj.lziapi.com` / `lzizy1.com`）。

如果源列表硬编码在 APK 里，**换一次域名就得重新发版让用户手动更新**，不可维护。

### 三层配置结构

| 层级 | 作用 | 优先级 |
| --- | --- | --- |
| 内置默认 | 打包进 App，保证首次安装即可用 | 最低 |
| 远程配置 | 从 URL 拉取，换域名只改这个 JSON | 中 |
| 手动覆盖 | App 内粘贴，应急用 | 最高 |

生效优先级：**手动覆盖 > 远程配置 > 内置默认**

### 怎么用

App 内进「我的 → 资源源」，可以：

- 填一个配置 URL，点「更新」拉取最新源列表
- 粘贴 JSON 手动导入
- 单独开关某个源（排查用）
- 「复检可用性」并发探测所有源的真实状态
- 「复制当前配置」导出分享或备份

### 配置 JSON 格式

```json
{
  "version": 1,
  "updatedAt": "2026-10-16",
  "sources": [
    {
      "key": "lzi",
      "name": "量子资源",
      "api": "http://cj.lziapi.com/api.php/provide/vod/",
      "enabled": true,
      "weight": 100,
      "note": "备注（可选）"
    }
  ]
}
```

**校验规则**（远程配置不可信，必须校验）：

- `key` 只允许 `[a-zA-Z0-9_-]`，1~32 字符（因为它会进 URL 路径与 nginx location）
- `api` 必须是 `http/https`
- `key` 重复的会被丢弃（重复 key 会导致相互覆盖）
- 至少要有 1 个合法源，否则整份配置被拒绝

配置可以放在任何地方（GitHub Gist、自己的站点、对象存储直链）。App 只负责拉取。

### 浏览器版的额外约束

浏览器版的代理 location 是按**内置源列表**生成的，所以浏览器版改了源列表需要：

```bash
npm run gen:nginx      # 重新生成服务端配置
# 然后重载 nginx
```

App 版直连源站，没有这个限制。设置页会按当前运行环境给出对应提示。

## 六、安装到手机

### Android

1. 把 `app-debug.apk` 传到手机（数据线 / 网盘 / `adb install`）
2. 手机上允许「安装未知来源应用」
3. 点击安装

用 adb 直接装（需开启 USB 调试）：

```bash
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

### iOS

**Windows 上无法构建 iOS**，需要 macOS + Xcode。而且：

- App Store 审核会拒绝影视类（同侵权理由）
- 侧载需要开发者账号（$99/年）+ 签名，**签名 7 天或 1 年就过期**，要重新签

iOS 实际可行的替代方案是 **PWA**：用 Safari 打开网页版 → 分享 → 添加到主屏幕。

## 七、已知限制（如实说明）

1. **只能侧载，不能上架**
   Google Play 与国内应用商店都会因影视侵权下架并封号。所以只能自己装、给朋友装。

2. **APK 可被反编译**
   包里的源域名一览无余。**不要公开分发**——公开传播会让「侵犯著作权」的定性风险实质性上升。

3. **播放仍用 hls.js（WebView 内）**
   已验证可行（CDN 带 `ACAO: *`，且已开启 `allowMixedContent`）。
   若要更好的体验（硬件解码、后台播放、画中画、省电），应换成原生播放器
   （Android ExoPlayer / iOS AVPlayer），这属于后续优化项，本次未做。

4. **首次启动需要网络**
   内置源列表在包里，但资源数据要联网取源站。没有离线缓存。

5. **源站稳定性不受控**
   源站会限流、换域名、关站。已做多源冗余 + 单源失败不影响整体 +
   设置页可复检可用性，但这需要长期运维。

### 顺带修掉的一个真实 bug

Vite 的文件监视器在 Windows 上遇到原子写入产生的临时目录
（`src/api/.sources.js.<pid>.<uuid>.tmpdir/sources.js.tmp`）会抛
`EBUSY: resource busy or locked` 并**直接让 dev server 崩溃**。

已在 `vite.config.js` 中加入忽略规则：

```js
server: {
  watch: { ignored: ['**/.*.tmpdir/**', '**/*.tmp', '**/*.swp', '**/.~*'] },
}
```
